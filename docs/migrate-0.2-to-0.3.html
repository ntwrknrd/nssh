Release candidate beta guide

Migrate nssh 0.2 to 0.3

A short guide for moving your saved hosts and automatic logins to the nssh 0.3 release candidate.

Source: nssh 0.2.4 Target: nssh 0.3 RC macOS and Linux Updated 2026-08-06
Keep your nssh 0.2 files until you finish testing.

Version 0.3 uses new settings and does not automatically convert your 0.2 setup. Do not run nssh self reset or delete your old files during the beta.

Start here

Choose how you want to migrate

Most users should ask an agent that has the nssh skill to guide or perform the migration. If you prefer to do it yourself, the manual path below has four steps.

Ask an agent

Give this prompt to Codex or another agent with the nssh skill installed:

Use the nssh skill to migrate my nssh 0.2 setup to 0.3. Back up my existing setup first, explain any choices I need to make, never display or copy my passwords, and test a host with me before cleanup.

The skill teaches agents the current nssh commands, file changes, credential options, and safe migration process.

Do it yourself

  1. Back up nssh 0.2.
  2. Install and set up nssh 0.3.
  3. Import your hosts and reconnect credentials.
  4. Test your usual logins.
What to expect

The three changes that matter

  • Setup is new. nssh 0.3 creates new YAML settings instead of using the old TOML file.
  • Passwords live elsewhere. Choose SOPS+age, 1Password, or Bitwarden; nssh securely retrieves them when you connect.
  • Connecting is simpler. Use nssh HOST, just as you would use ssh HOST.
Step 1

Back up nssh 0.2

Before installing the RC, make a private backup of your nssh folder and SSH configuration: 

backup="$HOME/nssh-0.2-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$backup"
cp -a "$HOME/.config/nssh" "$backup/config-nssh" 2>/dev/null || true
cp -a "$HOME/.local/share/nssh" "$backup/share-nssh" 2>/dev/null || true
cp -a "$HOME/.local/state/nssh" "$backup/state-nssh" 2>/dev/null || true
cp -a "$HOME/.ssh/config" "$backup/ssh-config" 2>/dev/null || true
cp -a "$HOME/.ssh/conf.d" "$backup/ssh-conf.d" 2>/dev/null || true

If you customized where nssh stores files, ask your beta coordinator or an agent using the nssh skill to help confirm the backup. Keep this folder private because it may contain encrypted credentials and host names.

Step 2

Install and set up nssh 0.3

Follow the RC installation instructions from your beta invitation, then start the guided setup: 

nssh --version
nssh self init
Which credential option should I choose?

Choose the password manager you already use. If you do not use 1Password or Bitwarden, choose SOPS+age. Never type a password into an nssh YAML file.

Step 3

Import your hosts

nssh can import the hosts you already use from your SSH configuration:

nssh self import ssh-config

Review the preview and accept it when the host names and usernames look right. Then use the guided inventory command to connect a host or group to the credential provider you chose: 

nssh inv list
nssh inv set --help

The help shows how to update a host or group. If your 0.2 setup used contexts or shared passwords across many hosts, this is the point where the nssh skill is especially useful.

Step 4

Test the hosts you normally use

Start with one familiar host. The login should work without putting a password on the command line:

nssh YOUR-HOST
0 of 4 tests complete

Keep your 0.2 backup for the entire beta, even after all four tests pass.

If something goes wrong

Stop and get help

Do not reset nssh or delete files. Ask your beta coordinator or an agent using the nssh skill to inspect the setup.

Use the nssh skill to troubleshoot my 0.2 to 0.3 migration. Inspect my setup without showing secrets or connecting to a host until I approve it. Preserve my 0.2 backup.
I need to return to 0.2 now

Reinstall the saved 0.2 release and restore the nssh and SSH folders from the same backup. Keep the 0.3 files separate so they can be inspected later.
