Which REPL TUI shape fits nssh?

The bottom input stays fixed in every option. The difference is how fanout work and output are represented above it.

nssh repl - transcript
@acm-lab-agg-sw(1,2) show hostname
----- acm-lab-agg-sw1.custcbb.local | show hostname -----
Hostname: acm-lab-agg-sw1
FQDN: acm-lab-agg-sw1.custcbb.local
----- acm-lab-agg-sw2.custcbb.local | show hostname -----
Hostname: acm-lab-agg-sw2
FQDN: acm-lab-agg-sw2.custcbb.local
nssh> @select:group:local/lab show version

A. Transcript First

Closest to an agentic coding TUI: scrollback above, fixed prompt below, minimal live status.

nssh repl - active batch
Targets
done sw1
run sw2
wait sw3
wait sw4
acm-lab-agg-sw1 | show interfaces status
Et1 connected in Po1
Et2 connected in Po2
Et55/1 connected routed 100G
nssh> @acm-lab-agg-sw(1,2) show interfaces status

B. Split Status

Left rail shows target state while the main pane shows the selected/completed output.

nssh repl - jobs
done 2/2 show hostname
acm-lab-agg-sw1, acm-lab-agg-sw2
running 4/12 show interfaces status
12 targets, concurrency 12
failed 1/3 show ip bgp summary
press enter on row to inspect output
nssh> @select:provider:netbox-prod show hostname

C. Job Dashboard

Best for long-running batches and history, but heavier than the current REPL concept.

My recommendation

  • Start with A plus a tiny active-batch status line.
  • It preserves raw command output and avoids building a job manager too early.

Risk to avoid

  • Do not make raw network output live inside tiny cards.
  • The first version should be keyboard-first, not mouse-first.
