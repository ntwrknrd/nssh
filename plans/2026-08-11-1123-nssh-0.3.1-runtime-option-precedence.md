# nssh 0.3.1 Runtime Option Precedence Hotfix

## Status

Proposed implementation plan for `v0.3.1`.

## Outcome

Make every explicit runtime SSH option take precedence over resolved nssh
configuration in every applicable SSH subprocess path, while retaining the
small set of nssh-enforced security arguments. Correct the related captured
remote-command bug that turns the connection timeout into a deadline for the
entire command.

The motivating failure is a captured command against ACM-CORE2 that is killed
at approximately the default 30-second connection timeout. A caller-side
120-second timeout and `-o ConnectTimeout=60` cannot extend that command in
`v0.3.0`.

## Release Contract

The hotfix must preserve these contracts:

- OpenSSH owns SSH option grammar and the effective behavior of repeated
  options.
- Explicit runtime options precede resolved YAML and inventory policy.
- Prepared host-key pins remain authoritative over ordinary runtime and
  configured options.
- nssh continues to disable ambient OpenSSH configuration with `-F none`.
- `ssh.connection.timeout` bounds connection establishment only. It does not
  bound remote-command execution.
- A caller-provided context remains authoritative for cancellation or an
  overall execution deadline.
- Remote commands continue to preserve distinct stdout, stderr, output order,
  and the remote exit status.
- SSH and SCP continue to share resolved endpoint, proxy, authentication, and
  host-key policy.

The effective precedence is:

1. nssh-enforced host-key preparation and `-F none`.
2. Explicit runtime SSH options.
3. Resolved inventory and YAML SSH options.
4. Derived nssh defaults, including the configured connection timeout when no
   higher-precedence `ConnectTimeout` exists.

This is precedence, not a custom replacement language. Options that OpenSSH
treats as repeatable retain native OpenSSH behavior after nssh orders their
sources correctly.

## Observed Defects

### Captured command deadline

`runResolvedRemoteCommand` copies `ssh.connection.timeout` into
`captured.Request.Timeout`. `captured.Runner.Run` then wraps the entire SSH
process with `context.WithTimeout`. The default 30-second connection timeout
therefore kills a valid long-running command and commonly surfaces as SSH exit
code `-1`.

### Runtime option loses to configuration

The builders generally emit resolved configuration before runtime arguments.
OpenSSH keeps the first obtained value for most scalar options, so a later
runtime option such as `-o ConnectTimeout=60` cannot override the earlier
configured value.

### Internal effective-option model disagrees with OpenSSH

`effectiveSSHOption` scans all occurrences and returns the last value. Several
mux and control decisions therefore model runtime precedence logically while
the emitted argv gives OpenSSH the opposite precedence. Tests currently assert
argv shape without verifying the effective OpenSSH value.

### Precedence logic is duplicated

Interactive, captured, mux check, mux start, control, host-key probe, and SCP
paths assemble arguments independently. Local checks for port, timeout,
askpass, and pinned host-key options can diverge even when they represent the
same connection policy.

## Design

### 1. Introduce one precedence-aware option composer

Add a connector-owned helper that composes the option portion of an OpenSSH
invocation from explicit inputs:

- prepared or enforced options;
- raw runtime options;
- rendered resolved SSH configuration;
- derived fallback options;
- SSH verbosity; and
- the applicable SSH or SCP option dialect.

The helper must not own target or remote-command grammar. Existing callers keep
responsibility for placing the target and command after all options.

The composer must:

- keep prepared host-key arguments first;
- emit exactly one authoritative `-F none`;
- place runtime options before resolved configuration;
- add a derived scalar default only when no higher-precedence value exists;
- retain the original order of runtime arguments;
- preserve OpenSSH repeated-option behavior rather than deduplicating options
  indiscriminately; and
- expose effective-option lookup using the same ordered representation used to
  build argv.

Do not add a second SSH grammar parser or convert raw runtime arguments into
YAML. Reuse the existing bounded option parsing helpers and add only the
semantic handling required for precedence and short-option aliases already
accepted by `PreprocessArgs`.

### 2. Make effective-option lookup first-value aware

Change effective scalar lookup to return the first applicable value from the
final precedence order. Cover split and joined forms, including:

- `-o ConnectTimeout=60`;
- `-oConnectTimeout=60`;
- `-o "ConnectTimeout 60"`; and
- short aliases already handled specially, such as `-p` for `Port`.

Keep repeated options intact. The lookup helper is for decisions that require
one effective scalar, not for rewriting all OpenSSH options.

### 3. Separate connection timeout from command timeout

Rename `captured.Request.Timeout` to `ConnectTimeout` and remove the internal
`context.WithTimeout` from `captured.Runner.Run`.

`ConnectTimeout` may contribute only an OpenSSH `ConnectTimeout` fallback. The
parent context passed into the runner continues to reach
`exec.CommandContext`, so caller cancellation remains effective.

Do not add a replacement nssh-wide command timeout. Overall command deadlines
belong to callers unless a separate product requirement is approved later.

### 4. Adopt the composer in every applicable execution path

Migrate these paths without changing their target or command behavior:

- interactive SSH in `internal/ssh/connector/args_unix.go`;
- captured remote commands in `internal/ssh/captured/runner.go`;
- mux check and mux start in `internal/ssh/connector/muxcheck_unix.go`;
- control commands in `internal/ssh/connector/control_unix.go`;
- interactive host-key probes in `internal/connect/hostkey_probe.go`; and
- SCP construction in `internal/cli/cp/cp.go`, accounting for SCP-specific
  flag spellings such as uppercase `-P` for port.

Review diagnostic connection tests and host-key scans separately. Migrate only
those that combine runtime and resolved configuration; retain intentionally
isolated probe arguments where no runtime/config precedence question exists.

### 5. Preserve enforced security options

Prepared `UserKnownHostsFile`, `StrictHostKeyChecking`, and the negotiated
`HostKeyAlgorithms` pin must stay ahead of conflicting runtime or configured
values. The composer must make this exception explicit rather than relying on
call-site append order.

Askpass safety options used by non-authenticating host-key probes remain
enforced. Runtime options must not re-enable password delivery during a probe.

Document these as nssh runtime enforcement, not configuration precedence
exceptions.

## Implementation Sequence

### Phase 1: Lock the contract with failing tests

Add focused tests before changing production behavior:

- A captured request with `ConnectTimeout=30s` receives no internally added
  context deadline.
- An existing parent deadline is still visible to the SSH executor.
- Runtime `ConnectTimeout=60` is effective over configured `30` in captured and
  interactive builders.
- Runtime scalar options override conflicting YAML values in each migrated
  builder.
- Split and joined `-o` forms behave identically.
- Relevant short forms, including `-p`, override equivalent configured
  directives.
- Runtime repeated options retain native ordered behavior.
- Runtime `ControlMaster=no` disables a configured persistent mux.
- Prepared host-key pins remain first and effective over conflicts.
- SCP runtime flags and resolved SSH options have the intended precedence.

Where available, use `ssh -G -F none` in a bounded integration test to verify
effective scalar values rather than inferring them solely from argv order.
Keep deterministic unit assertions for platforms or environments where that
integration check is unavailable.

### Phase 2: Implement shared composition

Add the minimal connector helper and migrate interactive SSH first. Update
effective-option lookup to use first-value semantics over the final ordered
arguments. Keep target, username, port, TTY, and remote-command placement in
their existing owners.

### Phase 3: Fix captured command semantics

Rename the request field, remove the process-wide timeout wrapper, and migrate
captured argv construction to the shared composer. Verify output draining,
highlighting, askpass, mux reuse, and exit-code tests remain unchanged.

### Phase 4: Migrate auxiliary SSH paths

Move mux, control, host-key probe, and applicable SCP option construction onto
the shared precedence rules. Remove duplicated effective-option checks only
after their callers have equivalent focused coverage.

### Phase 5: Verify the release candidate

Run focused package tests throughout development, then the repository test
target. Build the binaries and exercise representative effective-option
read-backs without connecting to production targets.

## Expected File Scope

Production changes should remain concentrated in:

- `internal/ssh/connector/options.go` and a narrowly named Unix composer file;
- `internal/ssh/connector/args_unix.go`;
- `internal/ssh/connector/muxcheck_unix.go`;
- `internal/ssh/connector/control_unix.go`;
- `internal/ssh/captured/runner.go`;
- `internal/connect/connect.go`;
- `internal/connect/hostkey_probe.go`; and
- `internal/cli/cp/cp.go` only where SCP precedence needs alignment.

Update the corresponding focused test files. No configuration schema, command
help, generated help snapshot, credential provider, inventory merge, recording,
or highlighting changes are expected.

If implementation reveals that SCP cannot safely reuse the same option
composer because of incompatible grammar, keep a small SCP adapter over the
same ordered option plan rather than generalizing the connector API further.

## Acceptance Criteria

- A remote command may run longer than `ssh.connection.timeout` when its parent
  context remains active.
- Parent cancellation still terminates the underlying SSH subprocess.
- `-o ConnectTimeout=60` is effective when configuration specifies 30 seconds.
- Explicit runtime scalar and boolean SSH options are effective over resolved
  YAML or inventory values across interactive, captured, mux, control, and
  probe paths.
- Short runtime aliases have the same precedence as their `-o` equivalents.
- Repeated options preserve native OpenSSH ordering and behavior.
- Prepared host-key pins and no-auth probe constraints cannot be displaced by
  ordinary runtime or configured options.
- Runtime mux disablement prevents mux checks and starts even when mux is
  enabled in configuration.
- SSH and SCP retain resolved endpoint, proxy, authentication, and host-key
  behavior.
- Captured stdout, stderr, event ordering, highlighting, and remote exit status
  remain unchanged.
- Focused tests, `make test`, and `make build` pass.
- No help snapshot or configuration example changes are required unless the
  implementation changes user-visible syntax, which this plan does not permit.

## Verification Commands

Run from the repository root:

```bash
go test ./internal/ssh/connector ./internal/ssh/captured ./internal/connect ./internal/cli/cp
make test
make build
```

Use local effective-configuration checks with non-routable example targets;
they must not initiate a connection:

```bash
ssh -G -F none -o ConnectTimeout=60 -o ConnectTimeout=30 example.invalid
ssh -G -F none -o ControlMaster=no -o ControlMaster=auto example.invalid
```

For the captured deadline regression, use an injected executor in unit tests so
the test observes context deadlines without sleeping for 30 seconds or opening
a network connection.

## Risks And Controls

- **Security option displacement:** Keep enforced host-key and probe options in
  a distinct highest-precedence input and test conflicting runtime values.
- **Repeated-option regression:** Do not deduplicate globally. Test
  `IdentityFile`, forwarding, and algorithm-list cases separately from scalar
  lookup.
- **Builder drift:** Require each SSH subprocess builder to consume the shared
  ordered option plan; retain call-site tests for target and command placement.
- **SCP grammar mismatch:** Use an explicit SCP adapter and test `-P` versus
  SSH `-p` semantics.
- **Context regression:** Test both absence of an internally manufactured
  deadline and preservation of a caller deadline.
- **Over-generalization:** Do not introduce configuration fields, command-timeout
  flags, compatibility layers, or a complete replacement OpenSSH parser.

## Rollback

The hotfix is code-only and does not migrate configuration or persisted state.
Rollback consists of reverting the `0.3.1` change and reinstalling `v0.3.0`.
Operators returning to `v0.3.0` must again avoid captured commands longer than
the configured connection timeout; this limitation must be stated if rollback
is required.
